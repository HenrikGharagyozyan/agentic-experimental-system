### Расхождения ТЗ и статей (следуем самосогласованной физике)

1. **Знак J (Delloye et al. 2023, ур. 1).** В статье напечатано
   `H = −Σ J_ij σ_i σ_j = −I` и `J_ij = −Σ_m Re(t_im t_jm)`. Эти две записи несовместимы:
   из `I_m = |Σ_i t_mi σ_i|²` следует `I = Σ_ij σ_i σ_j Re Σ_m t_mi conj(t_mj)`, т.е.
   `J_ij = +Re Σ_m t_mi·conj(t_mj)` (как в ТЗ). Принимаем форму из ТЗ; обязательный тест
   «H через T == H через J» это проверяет.
2. **Overlap реплик.** Delloye определяет `q_αβ = 1 − |Σ_i (X_i^α − X_i^β)|/N` (в тексте
   формула, судя по всему, искажена при вёрстке) и строит распределение `P(|q|)`. Мы
   реализуем стандартный параметр Паризи `q = (1/N) Σ σ_i^α σ_i^β` и используем `|q|`,
   потому что H инвариантна к глобальному перевороту σ → −σ (интенсивность не меняется
   при умножении поля на −1). Как и в статье, q считается по «зоне интереса» — спинам,
   которые реально связаны с целевыми модами (см. этап 2).
3. **Batch-flip.** В эксперименте Delloye группа уменьшается от 12% пикселей до 1
   (последние ~600 итераций — по одному спину); в их численной модели переворачивают по
   одному спину, ~10N итераций до плато. Реализуем расписание «от initial_batch_fraction
   к 1 спину», доля — параметр процедуры.
4. **SPR / DPR / MPR (Zhao & Chi 2020).** SPR = GS, где Фурье-преобразование заменено
   Fresnel-преобразованием на расстояние z — ложится в общий интерфейс
   «пропагатор + целевая амплитуда → фазовая маска». DPR/MPR используют каскад из 2..n
   фазовых масок в разных плоскостях (в статье — для шифрования изображений); в нашей
   схеме один SLM, поэтому они оставлены как `TODO(later)`.

## Этап 1. Device Registry и Safety Validator

**Что сделано**
- `schemas/devices.py`: у `ParameterSpec` появился `default` (только для необязательных
  параметров); новый `RegistryDocument` (корень файла реестра: `name`,
  `simulation_only`, `notice`, `devices`); проверки уникальности id устройств, операций и
  параметров; методы `DeviceSpec.operation()` / `OperationSpec.parameter()`.
- `devices/yaml_registry.py` — `YamlDeviceRegistry`: читает YAML, валидирует Pydantic'ом и
  **при загрузке** проверяет, что каждый default сам проходит проверку своей спецификации.
- `devices/validator.py` — `SafetyValidator`: проверяет каждую команду
  (unknown_device / unknown_operation / unknown_parameter / missing_parameter / wrong_type /
  wrong_unit / out_of_range). Ничего не исправляет и не обрезает.
- `configs/devices/simulation.yaml` — вымышленные sim-устройства по ролям + виртуальное
  устройство `procedures` (calibrate_transmission_matrix, run_ising_optimization, focus).

**Ключевые решения и почему**
- **Строгие типы.** `bool` никогда не считается числом (в Python `True` — это `int`!),
  а `5.0` не принимается для `int`-параметра. LLM получит понятное сообщение и исправит.
- **NaN/inf отклоняются явно.** Сравнения с NaN всегда False, поэтому без отдельной
  проверки `nan` «прошёл» бы любой диапазон.
- **Единицы — точное совпадение**, без конвертации (мВт ≠ Вт): конвертация — место для
  ошибок, а LLM пусть пишет ровно то, что в реестре.
- **Defaults в реестре, а не в коде backend.** Это тоже «факты об устройстве», поэтому их
  источник — только реестр. Backend берёт defaults из реестра.
- **Параметры команд — только скаляры.** Целевые моды задаются как `n_targets` +
  `target_separation` (в макропикселях), а не списком — проще проверять диапазоны.
- **N ≤ 256** через `grid_side ≤ 16` (N = grid_side²) — тесты остаются быстрыми.
- **Генератор → среда** — явно помеченная гипотеза симуляции в описании устройства.

**Новые понятия**
- *Defense in depth* (эшелонированная защита): одна и та же проверка выполняется в
  нескольких местах (оркестратор перед `execute()` и сам hardware backend), чтобы ошибка
  в одном слое не пропустила опасную команду к устройству.

## Этап 2. Scientific Core: оптика, модели T, Изинг, метрики

**Что сделано** (`src/experimental_system/scientific_core/`)
- `geometry.py` — квадратные сетки SLM (N = side²) и камеры (M = side_cam²) в одной системе
  координат (единица — макропиксель SLM); детерминированный выбор целевых мод
  (`n_targets` + `separation`).
- `transmission.py` — модели T: **UTC** (i.i.d. circular Gaussian, дисперсия 1/N — толстый
  рассеиватель, all-to-all) и **тонкий рассеиватель** `T = g ⊙ w`,
  `w_mi = exp(−d_mi²/(2ℓ²))`, с нормировкой строк.
- `optics.py` — кодирование спинов фазой (+1→0, −1→π), `E_out = T·E_in` (одиночно и
  батчем), квантование фазы SLM, `CameraModel` (8 бит, насыщение 255, экспозиция и
  мощность масштабируют сигнал, read-шум + shot-подобный шум).
- `ising.py` — J через T, H оптически и через J, точный минимум перебором (N ≤ 20),
  относительный energy gap, намагниченность, overlap Паризи, зона интереса.
- `metrics.py` — построчная корреляция T (инвариантна к фазе строки), enhancement η,
  теория `π/4·(N−1)/N_f + 1`, детектор плато.

**Ключевые решения и почему**
- **Фиксированный беспорядок + огибающая.** В тонкой модели случайная часть `g` хранится
  отдельно, а напряжение генератора меняет только ℓ. Так «та же среда при другом
  напряжении» описывается согласованно, и сравнение двух напряжений в сценарии 3
  физически осмысленно (а не «две случайные среды»).
- **Нормировка «средняя интенсивность моды ≈ 1»** для случайного входа: тогда η = I_focus
  буквально, и масштаб камеры (gain·мощность·экспозиция) настраивается понятно.
- **Перебор основного состояния использует симметрию** H(σ) = H(−σ): фиксируем σ₀ = +1 и
  считаем 2^(N−1) конфигураций векторизованно кусками — N = 16 занимает миллисекунды.
- **Многофокусная теория.** Huang et al.: для N_f фокусов «добавить N_f в знаменатель» —
  трактуем как `π(N−1)/(4N_f) + 1` (знаменатель первого слагаемого). Для бинарной 0/π
  модуляции эта формула не используется (как требует ТЗ).

**Новые понятия**
- *UTC-модель*: каждый элемент T — независимая комплексная гауссова величина; свет из
  любого пикселя SLM попадает в любую моду камеры (полностью связанная система спинов).
- *Матрица Маттиса*: при одной целевой моде `J_ij = Re(t_i·conj(t_j))` имеет ранг ≤ 2, т.е.
  задача проще общего спинового стекла — поэтому одна мода даёт «ферромагнитное»
  основное состояние (с точностью до калибровочного узора фаз t_i).

## Этап 3. Phase retrieval: GGS и GS

**Что сделано** (`scientific_core/phase_retrieval.py`)
- `generalized_gs` — GGS 1 / GGS 2 / GGS 2-1 (Huang et al. 2021, ур. 3–4): псевдообратная
  `P⁺` считается один раз, остановка строки по корреляции `X_f` с `X_{f−2}` > 0.999999,
  сошедшиеся строки исключаются из итераций, максимум 1000 итераций на стадию.
- `focusing_phases` — фазовое сопряжение `φ_i = −Arg(x̂_mi)` (для двух фокусов — сумма строк).
- Общий интерфейс `Propagator` (forward/backward) и одна функция `gerchberg_saxton`:
  `FourierPropagator` — классический GS; `FresnelPropagator` — SPR (Zhao & Chi);
  `MatrixPropagator` — GS через известную T (целевая картина через рассеивающую среду).
- DPR/MPR — `TODO(later)` с описанием в docstring модуля (нужен каскад фазовых плоскостей).

**Проверка против статьи** (N = 64, γ = 4, без шума, seed фиксирован)

| Алгоритм | корреляция строк T | η / η_теор |
|---|---|---|
| GGS 1 | 0.73 | 0.65 |
| GGS 2 | 0.94 | 0.86 |
| GGS 2-1 | 1.00 | 0.98 |

Совпадает с Huang et al. (Fig. 2: GGS 2-1 ≈ 98%, GGS 2 ≈ 87%, GGS 1 застревает в
локальных оптимумах). Тест фиксирует порядок `GGS 2-1 > GGS 2 > GGS 1`.

**Ключевые решения**
- Корреляция для остановки берётся по модулю скалярного произведения — инвариантна к
  фазе строки (как и метрика качества T).
- В `MatrixPropagator` обратный шаг — псевдообратная `T⁺` (решение наименьших квадратов),
  а не `T†`: при M < N это точнее восстанавливает поле на SLM.

**Новые понятия**
- *Псевдообратная матрица (Мура–Пенроуза)* `P⁺`: «лучшее возможное обращение»
  неквадратной матрицы. Для переопределённой системы `P·x = e` (L > N уравнений) даёт
  решение наименьших квадратов: `x = P⁺·e`. Пример: `np.linalg.pinv(P) @ e`.
- *Phase retrieval*: камера измеряет `|E|²`, фаза теряется. GS-подобные алгоритмы
  чередуют два ограничения («амплитуда такая, как измерено» и «решение линейно / маска
  фазовая»), пока оценка не перестанет меняться.
